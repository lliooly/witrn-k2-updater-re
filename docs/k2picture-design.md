# K2Picture macOS 首版设计

日期：2026-10-08。状态：用户已批准实现。范围：现有 SwiftUI 应用中的完整表盘编辑、开机图管理和设备写入。

## 目标与方案

首版供个人使用，继续支持 macOS 13 及以上、Apple Silicon 和 Intel Mac，沿用本地临时签名及内置 Python HID 后台。

推荐把完整编辑器整合进现有应用。只上传官方文件实现较快，但不能解决编辑不便；另建独立编辑器会重复设备连接和打包工作。用户已选择完整编辑并写入的范围。

## 界面与操作

主窗口提供“固件升级”“表盘”“开机图”三个入口，共用设备状态和后台任务状态。固件升级保留已验证的备份、校验与升级流程。执行 USB 操作期间锁定设备选择及其他设备操作，写入期间继续阻止退出。

表盘页提供 240 × 240 的逻辑画布，可缩放查看，支持点击选择、拖动定位和键盘微调。右侧显示选中元素的名称、显示开关、X/Y 坐标、颜色及设备支持的字号；数字元素提供相应的精度选项。可编辑项以官方程序与固件实际支持的项目为准。导入参数中尚未对应到编辑控件的项目和保留字节保持原值。

背景图支持 BMP，并通过 macOS 的图片解码能力接受 PNG、JPEG。不同尺寸图片必须先明确裁剪或缩放到目标尺寸，再用于写入。预览使用固定示例读数；标明字体预览与实机可能存在差异，不把示例读数作为设备实时数据。

开机图页独立提供 235 × 235 预览、导入、裁剪或缩放及写入操作。

设备连接不影响离线编辑。窗口里只展示可用功能，模拟设备、故障注入和开发测试命令继续留在开发工具中。

## 文件与工程

支持导入、编辑、导出官方 `.pic` 参数文件，并单独导出对应的 BMP 图片。解析使用明确的二进制字段与范围检查，不加载或执行文件中的代码。严格检查长度、标记及可解释字段，错误信息指出具体问题。

增加应用自己的工程文件，封装布局、背景和可选开机图，便于保存和重新打开。采用带版本号的 Codable 文档，将图片数据包含在工程中，避免移动文件后丢失背景。工程与官方 `.pic` 的区别在文件选择器和导出菜单中明确显示。

导入 `.pic` 后保留未知字段及保留字节。仅编辑颜色等一个字段时，不重置其他参数。导出官方文件不依赖本应用工程格式。

## 模块与数据流

Swift 的核心模块负责参数模型、`.pic` 编解码、工程文档和参数验证；AppKit/Core Graphics 负责图片解码、裁剪及 RGB565 转换；SwiftUI 负责画布、属性编辑器、文件操作和任务状态。

Python 后台复用现有 HID 传输与设备身份核对，增加资源区读取、备份及写入状态机。前台提交准备完成的数据文件和摘要，后台在打开 USB 前重新验证文件、类型、长度和设备身份。设备地址由经过静态分析确认的内部资源类型选择，界面不允许输入任意地址。

表盘图片、布局参数和开机图是三个独立写入项目。首版分别执行，并按每次操作实际结束后的设备状态提示重新进入 DFU，不假定官方要求分开烧录的流程可以合并成一次 USB 会话。

## 设备写入与恢复

每次写入先握手并核对 K2 身份，再完整读取该操作会擦除的扇区两遍。两遍一致且备份、摘要和清单已成功保存后，才允许擦写。

擦除范围包含对齐的完整扇区。若目标数据只占其中一部分，读出的相邻数据必须合并回写；不得因为写入 400 字节参数而丢失同扇区其他数据。每个资源写入后完整读回比较，失败立即停止，保留备份和阶段日志。

提供从本应用备份恢复对应资源的操作，恢复同样核对设备、类型、长度及摘要，并先备份当前状态。应用区固件升级、表盘资源写入与资源恢复使用各自范围限制。

实机首写在离线验证和备份能力完成后单独执行。届时展示具体目标、内容及备份结果，再由用户确认。

## 验证与完成条件

文件验证覆盖 `.pic` 的逐字节往返、单字段修改、保留数据、损坏文件和未知工程版本。图片验证用合成色块核对 RGB565、行列方向、尺寸及包头尾。

后台测试覆盖资源范围、扇区边界、邻接数据保留、双遍备份不一致、断连、错误回包和读回不一致。测试使用开发模拟设备，不在产品界面暴露入口。

两种架构均验证编译、打包和内置后台运行。实际 GUI 验证导入、编辑、保存后重开、导出及断开设备时的按钮状态。实机验证分别检查开机图、背景及参数效果，记录预览与设备字体的差异。

只有已确认资源编码、地址、扇区范围及结束流程的操作才启用真实写入。无法确认的部分必须明确报告，不能以未实现按钮或模拟成功替代完成。

## 已获得的证据

官方文档确认：开机图 235 × 235、背景 240 × 240，图片与参数分别写入，写入后需要在设备“设置 → 6 主题屏开关”中开启表盘。[官方说明](https://www.witrn.com/?p=2615)

对本地 K2Picture 1.1 程序进行静态方法恢复后，验证了 1330 个方法和 674 组代理映射。保存方法将 Pack=1 的结构体直接写入 `.pic`，总长 400 字节；前后标记为 `0xA55AA55A`。这为兼容编解码提供了依据。所有恢复程序集和反编译文本仅留在忽略的本地分析目录。
