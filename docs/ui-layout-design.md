# macOS UI 布局重构设计

日期：2026-10-08

## 目标与范围

将现有按钮罗列式界面重构为按任务组织的工作台，让用户首先找到上位机，其次找到固件升级，再找到自定义功能。虚拟 E-Mark 放入高级工具。

本次只调整 SwiftUI 界面结构、导航、展示状态和操作入口。复用现有 Store、BackendClient、K2Core 及 Python 后端，不更改通信协议、采集、文件格式、备份或写入流程。保留全部现有功能及操作保护。

在当前 checkout 工作，不创建 worktree 或新分支。不使用视觉伴侣。

## 现状

- ContentView 的维护页面在同一个 ScrollView 中顺序堆放设备卡片、业务页面、进度卡片和恢复／备份／日志按钮。
- 上位机单独实现连接区，连接入口与维护页的位置不同。曲线位于多组读数、设置和操作之后。
- 表盘、开机图和 E-Mark 将工程文件操作、编辑操作、设备读写并列，缺少主次。
- App 默认进入固件升级，不符合当前使用频率。

## 整体结构

窗口采用「左侧功能导航／中间工作区／右侧全局连接栏」，底部为固定任务状态区。继续采用 macOS 13+ 原生 SwiftUI 与现有系统控件风格，不引入第三方 UI 依赖。

左侧导航顺序：

1. 上位机（现有曲线与记录，默认进入）。
2. 固件升级。
3. 自定义分组：表盘、开机图。
4. 高级工具分组：虚拟 E-Mark。

分组标题用于导航组织，不新增独立首页。高级工具保持可见，不要求用户启用额外设置。

顶部条与红绿灯同处一条：左侧栏占住红绿灯所在的那条窄带，收起／展开按钮紧贴红绿灯右侧，不与「WITRN K2」标题同行；工作区顶栏从窗口最上沿开始，不再为系统标题栏留出空白带。窗口工具栏（只承载系统自带边栏按钮）整体隐藏，避免出现第二个入口。

macOS 26 及以上使用 `safeAreaBar` 承载工作区顶栏，并通过 `scrollEdgeEffectStyle(.soft, for: .top)` 让滚动内容在顶栏下方柔和模糊。顶栏不再铺满玻璃背景，操作按钮保留独立的玻璃胶囊；旧版系统保留材质顶栏布局。

左侧栏按钮使用系统 `.glass` 按钮样式及圆形边框；右侧维护菜单与连接栏开关各有独立的圆形 `.glassEffect(.regular.interactive())` 表面。两个按钮默认间距为 8 点，按住任一按钮时缩为 2 点，松开后恢复；`GlassEffectContainer` 的融合距离为 6 点，因此静止时分开、按住时相连。按钮组宽度与中心固定，按住时两个按钮各向中间移动 3 点，避免影响相邻控件。按压与指针反馈由系统处理，不叠加手写缩放或弹簧动画；连接状态图标不参与动画。旧版系统使用普通按钮与系统材质。

收起后侧栏连同按钮一起消失，顶栏左端在红绿灯右侧保留一个紧凑的展开按钮。收起／展开只改变显示，不切换当前页面，也不改动已打开的工程。

顶部工具栏展示当前页面或工程、保存状态和当前页面的常用文件操作。文件操作使用明确文字／标准图标及帮助提示；工程保存、导入文件和写入设备使用不同名称。保留现有快捷键、拖放和撤销／重做行为。

## 全局连接栏

### 固定位置与显示状态

连接栏由 ContentView 层持有，独立于各业务页面，位于窗口右侧，初始展开。展开宽度约 260 点；内容可独立滚动。工具栏提供带文字帮助的展开／收起按钮和简洁连接状态。

展开状态通过 AppStorage 保存；切换页面、连接状态变化、任务开始或完成均不得自动展开／收起。收起后，连接状态和展开入口始终可见。

切换页面只切换中间工作区，不重新创建 Store、不启动采集、不断开连接、不刷新设备、不清空已确认身份、不改变 DFU 确认，也不自动切换设备模式。侧栏中的设备信息和模式选择保持原位置；只有与当前任务有关的提示可以变化。

### 内容与操作

连接栏依次展示：

- 当前设备、接口选择和刷新入口。
- 当前会话状态，包含等待遥测、实时预览、记录、暂停、断开处理中、维护操作中及错误。
- 用户选择的连接用途：正常模式采集或 DFU 维护。切换用途只改变准备操作的展示，不调用后端、不暗示设备已进入对应模式。
- 正常模式的连接／断开，以及 DFU 的确认勾选和读取设备信息。
- 已确认的型号和固件版本；无法获取时显示「未读取」，不能将固件文件的目标版本作为设备当前版本。
- 当前页面要求的模式提示，以及模式不匹配时的下一步说明。

初始连接用途为正常模式。采集会话或维护任务占用设备期间，接口和用途选择禁用；正常模式采集期间保留断开操作，维护擦写期间保留现有不能取消的保护。

区分「发现接口」「已启动采集，等待有效遥测」「正在接收实时数据」和「已读取并确认 DFU 设备」。当前 MonitorStore.connected 在启动请求时就为 true，不能仅凭该字段显示已经接收数据。DFU 勾选仅表示用户确认，不代表已探测到 DFU；当前版本仅依据 UpdaterStore.identity 展示。

从上位机切换到固件升级时，正常采集继续，连接栏显示现有会话并提示：先断开，再按设备要求进入 DFU，并选择 DFU 维护、读取信息。页面导航本身不能执行这些步骤。

写入完成或失败后，现有 Store 可能清空设备身份和 DFU 确认。侧栏应据实显示需要重新确认，不能为了视觉稳定保留过期的「已连接／已确认」状态。连接稳定指入口和会话不因导航跳变，并非屏蔽真实状态变化。

现有后端未提供通用设备模式探测或普通模式版本查询，本次不新增这些能力，不根据接口存在猜测模式。采集掉线与超时沿用现有事件；DFU 信息只表示上次读取确认的结果。

## 上位机工作区

默认进入上位机。中央优先展示实时数据和曲线：

1. 顶部紧凑读数栏突出电压、电流、功率；温度、D±、累计值和设备运行信息作为次要读数。
2. 记录控制栏展示开始记录；记录中展示暂停／继续、停止并保存、采样数量和现有数据可支持的记录时间。连接控制只在全局连接栏。
3. 图表工具栏紧贴曲线，包含通道、时间窗口、跟随最新、全程概览、缩放和移动。
4. 曲线占据主体高度；沿用现有多通道绘制与拖选逻辑，不改变数据查询或渲染算法。
5. 工作区内的「记录设置」和「区间统计」使用可展开区域，不另占全局右侧栏。记录设置默认收起；拖选区间或显式请求统计时展开统计区域，不抢走键盘焦点。

历史记录使用工作区内的「实时／历史记录」切换入口。进入历史区域只展示列表和打开／导入入口，不断开采集；实际打开历史文件的可用条件沿用 Store 当前约束，并解释需要先断开时的原因。返回实时区域保留原会话和显示设置。

导出菜单跟随当前显示的记录，保留官方 CSV、官方 SQLite、完整本地 SQLite、选区导出及 PNG 功能。定位文件、清除预览和刷新记录列表归属相关记录区域。清除预览沿用现有会话重启行为，不能由页面切换触发。

无设备、无曲线时，工作区显示连接或打开历史记录的明确入口；连接入口只展开连接栏，不自动连接。加载、导出或查询中显示局部进度，不让图表工具挤到远处。

## 固件升级工作区

以「确认设备 → 选择固件 → 备份并升级」显示操作顺序。设备准备在右侧连接栏，中央不重复接口选择、刷新和 DFU 控件。

中央显示所选文件、检查结果以及当前版本／目标版本对照。突出「备份并升级」，保留「仅备份固件」作为次要操作。步骤状态由现有 Store 推导，不添加新的升级状态机。

保留原升级确认弹窗、合成固件拒绝、双遍备份、写后校验、失败停止和窗口关闭保护。升级进度固定在底部可见，不随工作区滚出。

## 自定义工作区

表盘：画布旁使用全部 17 个元素的逐行编辑表，直接展示显示、X/Y、颜色、字号和小数位，不再通过下拉框选择元素。宽窗并排、窄窗上下排列；元素编辑区不属于全局连接栏。背景操作归入背景区域；布局和背景的读取／写入按资源分别展示，不新增合并写入。

开机图：以图片预览和导入／替换为主要内容；裁剪沿用现有 Sheet，导出与移除放入相关图片操作区域。

共用顶部工程工具栏，保留打开、保存、另存为、新建、撤销和重做。文件导出归入「导出」，设备读取和写入归入单独的「设备操作」区域，不能将保存工程和写入设备混用。

设备操作不可用时，在对应区域展示可执行的原因提示。未连接设备仍可离线编辑和保存。布局、背景和开机图分别写入；完成后重新进入 DFU 的原流程保留。

## 虚拟 E-Mark 工作区

导航放在高级工具下。中央保留配置列表和选中配置编辑区；新建、复制、删除、排序和设为默认归属列表。工程文件操作移入工具栏，官方格式导入／导出使用单独菜单。

设备配置读取、复制数据读取和配置写入归属设备操作区域。复制数据结果出现在对应区域，保留添加和导出入口。原始 VDO／扩展字段默认折叠；字段校验、未保存保护、撤销和删除确认保持不变。

## 固定任务状态区与错误处理

底部状态区由窗口持有，切换页面后仍显示进行中的维护任务或采集状态。维护任务优先显示阶段、进度和可用的只读取消；采集显示记录／暂停／断开状态。无任务时使用紧凑高度。

完成结果提供对应备份／日志入口。恢复资源备份归入始终可发现的「维护」菜单，保持当前确认和备份校验流程。查看现有备份和日志也保留在维护菜单，沿用可用条件。

操作失败在状态区显示简短原因与展开详情入口，不自动重试，不以成功图标覆盖错误。文件导入或字段错误在相应工作区显示。收起连接栏后出现连接错误时，工具栏仍显示错误提示；不得自动展开侧栏。

## 组件边界与数据流

- ContentView：导航、全局侧栏、固定状态区和当前工作区组合。
- 连接栏组件：观察共享 UpdaterStore 和 MonitorStore，通过现有方法发起用户明确点击的连接操作；不拥有独立连接会话。
- 页面工具栏：根据当前页面将文件和编辑命令路由至原 Store。
- 各工作区：负责页面内部布局和局部展开状态，不管理全局连接栏生命周期。
- 状态区组件：从现有 Store 推导任务展示并提供既有取消／日志／备份操作。

布局使用新的 View 组件拆分职责，避免继续扩大 ContentView。UI 专用状态放在 View 或 AppStorage 中；不复制 Store 中的设备、连接或任务数据。正常模式的采集连接与 DFU 身份确认仍为两个已有流程，只统一展示和入口。

## 尺寸、可访问性与兼容性

继续支持 macOS 13。左导航约 150 点，连接栏约 260 点；窗口最低宽度以主要编辑区可用为准，目标为 1100 点、最低高度 720 点。默认窗口约 1280 × 880 点。侧栏展开时工作区可调整为纵向局部布局，避免关键按钮被截断；侧栏可收起释放空间。

使用系统文字、颜色和控件，支持浅色／深色模式。图标按钮提供 help 与可访问性标签；连接状态同时使用文字和图标，不只用颜色。新增布局不将常用动作藏入无名称的更多菜单。所有页面主操作及任务反馈不依赖滚动到页面底部。

## 验证与验收

实现后运行 Swift 编译和现有 Swift 测试；若涉及 Store 调整，仅针对实际新增行为补充有意义的测试。后端没有改动时，不新增后端测试或执行真实设备写入。

通过运行应用检查以下行为：

- 启动默认上位机，导航顺序和分组正确。
- 左导航收起／展开按钮在红绿灯右侧，展开时侧栏标题行、收起时工作区顶栏均不再出现系统空白条；收起后顶栏左端保留展开按钮，当前页面选择不因收起而改变。
- 连接栏在五个页面位置一致；展开状态跨页面和重启保留，状态变化不自动展开。
- 页面切换不调用连接／断开、刷新、探测或清除预览，不重置设备选择及有效确认。
- 采集／记录期间切到升级和编辑页面，会话持续；维护操作仍被阻止，本地编辑可用性沿用当前 Store 约束。
- 正常采集与 DFU 状态不混淆，未知版本不伪造；显式断开、模式准备和探测的入口清楚。
- 表盘、开机图、E-Mark 原有文件操作、编辑和设备操作都有入口，快捷键不回退。
- 上位机曲线在初始视口可见，记录设置不挤占主要图表；历史查看、区间统计、所有导出入口保留。
- 任务进度与错误在切换页面或收起侧栏后仍可见，资源恢复和备份／日志可发现。
- 默认与最低窗口尺寸、连接栏展开／收起、浅色／深色模式均无关键控件截断。

未连接真实设备时，将采集稳定性和真实升级交互明确记为未实机验证；界面检查不得隐式启动设备写入。

分段选择器统一使用 `AnimatedSegmentedPicker`：实时／历史及正常采集／DFU 维护共用选中背景，切换时以 0.22 秒缓入缓出滑动。动画限定在选择器内部；保留禁用状态、键盘左右切换及选中项辅助功能标记，开启“减少动态效果”时立即切换。
