# macOS 图形版

K2 Updater 使用 SwiftUI 窗口和已验证的 Python 升级核心。Python、HIDAPI 和协议查表数据随 `.app` 一起打包；运行应用不需要终端、Python 安装或开发环境。应用不包含官方固件。

## 布局与入口

应用默认进入「上位机」，随后是「固件升级」；「自定义」下包含表盘和开机图，「高级工具」下包含虚拟 E-Mark。

右侧设备连接栏在所有页面共用，通过顶栏唯一的链环状态按钮收起／展开，展开状态会保存。未连接时显示红色断链和对角斜线，确认连接后显示绿色链环；悬停可查看具体状态。选择「正常采集」或「DFU 维护」仅选择连接操作的用途，不会自动改变设备模式。切换功能页面也不会断开采集、自动探测或重置连接准备。设备状态依据实际采集和探测结果显示；发现接口不等于已连接，等待遥测不等于已经收到数据。

上位机将实时读数、记录控制和曲线放在主要工作区；采样及自动停止放在「记录设置」，区间计算放在「区间统计」。历史列表通过「历史记录」切换查看，切换到列表不会停止采集；实际打开／导入仍保留停止并保存的确认。全部记录、选区和曲线 PNG 的导出放在「导出」菜单。

表盘、开机图和 E-Mark 的工程打开、另存为、导入／导出统一放在顶部「文件」菜单，保存、撤销和重做在旁边。设备读写位于固定的「设备操作」区域，与本地工程保存分开。底部任务状态区始终可见；资源恢复、备份和日志也可以通过窗口工具栏的「维护」菜单访问。

## 使用

打开 `dist/K2 Updater.app`，也可以把它复制到「应用程序」。本次旁路交付文件为 `dist/K2 Updater 0.5.1.app`，避免替换尚在运行的旧版本；两者使用同一数据目录。使用新版前先正常断开并退出旧版，避免设备接口同时被占用。最低系统目标为 macOS 13，构建产物为 Universal 2，包含 Apple Silicon 和 Intel 架构。

首版通过窗口中的文件选择或拖入接收固件，不注册 Finder 双击固件的打开关联。

1. 从厂商渠道取得适合 K2 的 `.k2` 文件，在窗口中选择或拖入，检查型号和目标版本。
2. 按住设备减号键，从 CC1/HID 口使用数据线连接 Mac，进入 DFU。
3. 在右侧连接栏刷新设备、选择接口和「DFU 维护」，勾选「已按住减号键连接，进入 DFU」，点击「读取设备信息」。
4. 可先点击「仅备份固件」。点击「备份并升级」并确认后，程序仍会重新读取两遍完整备份；两遍一致并生成恢复容器后才擦写。
5. 等待正文读回校验、提交及退出完成，再检查设备屏幕上的版本。完成后可以直接打开备份文件夹或定位日志。

升级时不能更换固件、设备，正常关闭窗口和 ⌘Q 会被拦截；只读操作可以取消。系统强制退出、断电和拔线不受窗口保护控制。失败会停止流程并显示阶段与原因，不会自动重试；擦写后的失败需要保留备份并重新判断设备状态。

备份和日志默认位于 `~/Library/Application Support/K2 Updater/` 的 `Backups`、`Logs` 中；每次操作有独立目录或文件。备份包含 `flash.bin`、`app.bin`、`bootloader-and-info.bin`、恢复 `.k2` 和 `manifest.json`。恢复容器经过离线内容核对，恢复刷写本身没有实机验证。日志和备份可能包含设备信息，请勿直接公开。

图形界面只提供真实设备操作，已移除离线演示、故障注入和合成固件入口；启动参数也不能启用模拟界面。合成测试固件及其恢复容器仍会被拒绝写入真实设备。

## 表盘和开机图（0.3.0）

侧边栏提供「表盘」和「开机图」。未连接设备也可编辑。打开工程／`.pic` 使用 ⌘O，保存工程使用 ⌘S，另存为使用 ⇧⌘S；项目自己的 `.k2project` 文件包含布局、背景与开机图。工程修改可撤销／重做，关闭时提示保存。

表盘画布显示固定示例读数，可选 100%／150%／200% 缩放。点击选中元素后拖动，方向键微调 1 像素。全部 17 个已识别元素按行排列，可直接调整显示开关、X/Y、颜色（含透明度）、七档设备字号与数字小数位（电压／电流 2…7，功率／Wh 3…7，D±／CC1／CC2 2…3，与官方选项一致）。点击元素名称与画布选中保持同步；宽窗中画布和元素表并排，窄窗中上下排列。存储的 Y 是设备坐标，文字预览按官方保存方式加上字号高度，仍与实机字形及基线可能不同。未知元素和保留字节在导入、编辑和导出时保留。

背景为 240 × 240，开机图为 235 × 235。导入 BMP、PNG 或 JPEG 后，明确选择裁剪填满（可缩放和移位）、完整保留（黑色留边）或拉伸；确认后再用于写入。透明区域与留边填充黑色。导出菜单分别生成官方 `.pic` 和 24 位 BMP；工程与这两类官方文件不同。

读取设备资源必须先进入 DFU、刷新接口并读取设备信息。「读取并备份」会双遍读取完整扇区，保存原始数据并加载到工程；尚未设置有效资源时只保留原始备份并报告格式问题。每次资源写入先双遍备份、持久化数据和清单，再擦除、合并原扇区尾部数据回写，最后完整扇区读回比较。任何错误立即停止，失败不会发送退出命令。

背景、布局、开机图独立写入；每次完成后重新进入 DFU，再进行下一类写入。最终在 K2「设置 → 6 主题屏开关」开启自定义表盘。[厂商说明](https://www.witrn.com/?p=2615)

「恢复资源备份」选择本应用备份目录的 `manifest.json`，核对类型、摘要及设备信息后，先备份当前状态再恢复完整扇区。不接受任意地址，也不把开发模拟备份恢复到真实设备。`Resource Backups` 目录内包含 `sectors.bin`、`manifest.json`，以及读取操作生成的 `layout.pic` 或图片资源原始数据；图片原始数据是含标记的 RGB565 结构，并非 BMP。

## 虚拟 E-Mark（0.4.0）

侧栏新增「虚拟 E-Mark」，未连接设备也可编辑。读取设备配置后管理最多 10 组：添加、复制、删除、排序和设为默认。读取「复制数据」独立保存，可导出或添加到配置集合。

名称最多 18 个 Latin-1 字符，中文及超长输入会显示错误。PD 版本、VID/PID、XID、速度、电流、电压、EPR、端口、插头和软硬件版本可编辑；高级区域提供 11 个原始 VDO／消息头及附加字段。数字身份字段和 VDO 使用十六进制，附加字段使用十进制。修改位字段保留其他位并自动更新校验，无效输入不会写入记录，也阻止保存和设备写入。

「导入 .wtemark」可批量加入官方单条配置文件，「导出选中配置」生成 66 字节官方格式。「保存工程」生成本应用 `.k2emark`，保存全部槽位和默认组；⌘O、⌘S、⇧⌘S、撤销／重做跟随当前页面。表盘工程与 E-Mark 工程分别保存，关闭时分别保护未保存更改。新增配置是本应用生成的模板，需要根据所需身份调整，未冒充厂商预设。

设备操作需要 DFU 和读取设备信息。「备份并写入配置」仅更新配置集合扇区，保留复制数据、表盘和开机图；写前完整双遍备份，写后整个扇区读回校验。读取到空白或无效资源时仍保存原始备份并报告问题，不自动修复回写。「恢复资源备份」也支持 E-Mark 集合与复制数据的完整扇区恢复。备份目录中还保存 `configurations.k2emarkbin` 或 `copied.wtemark`；原始集合文件与 `.k2emark` 工程不同。

写入完成后重新上电，在 K2 菜单选择虚拟 E-Mark 和对应组。参数不会改变线材实际电气能力，设备开关和私有加密认证没有远程操作入口。静态证据及验证边界见 [E-Mark 分析](../reverse/K2EMARK.md)。

## 曲线与记录（0.5.0）

侧栏「上位机」提供曲线与记录。正常开机后连接 CC1/HID 口，不按减号进入 DFU；选择接口后连接即可预览。开始记录选择新 SQLite 文件，暂停仍可查看实时数据，停止或退出前提交记录。采集占用期间设备维护操作被阻止，本地表盘和 E-Mark 编辑仍可使用。

曲线支持拖选、起止秒数、缩放／移动、全程概览、跟随最新和可选温度／D±。记录设置 1／10／100 样本每秒或全部接收，是电脑端上限。自动停止默认关闭，可配置绝对电流或功率低于阈值持续指定时间。历史文件可离线打开，支持官方 CSV/SQLite、本地 SQLite 和 PNG 曲线导出。具体用法、存储及统计含义见 [曲线工具说明](k2-monitor.md)。

## 本地构建

需要 Xcode 命令行工具、支持目标架构的 Python 3.9 和依赖安装环境。目前构建脚本使用 Python 3.9；Universal 2 构建还要求 Python 解释器及标准库扩展包含两个架构。当前机器的 Xcode 内置 Python 满足这一点，其他机器应先检查自己的解释器。

```sh
python3.9 -m venv .venv-app
.venv-app/bin/python -m pip install -r requirements-app.txt
./script/build_and_run.sh --build-only
```

脚本会为项目专用 `.venv-app` 合并同版本 HIDAPI 的 arm64 / x86_64 扩展；它不修改系统 Python 或 CLI 的 `.venv`。Universal 2 的双架构导入验证在 Apple Silicon 上需要 Rosetta。依赖未缓存时需要网络。单架构构建可以设置 `K2_APP_ARCH=arm64` 或 `x86_64`，并使用匹配架构的 Python 环境。

直接运行 `./script/build_and_run.sh` 会构建后启动 `.app`，Codex 的 Run 操作指向同一入口。应用仍在运行时，脚本请求正常退出；若有任务阻止退出则停止构建，不强制杀进程。`--build-only` 供已关闭应用时使用。应用使用 ad-hoc 本地签名，不需要 Apple Developer Program，尚未使用 Developer ID 签名或公证；通过下载渠道分发时仍可能触发 Gatekeeper。

```sh
.venv-app/bin/python -m unittest discover -s tests -v
CLANG_MODULE_CACHE_PATH="$PWD/build/ModuleCache" \
SWIFT_MODULE_CACHE_PATH="$PWD/build/ModuleCache" \
swift test --package-path macos --disable-sandbox \
  --scratch-path "$PWD/build/swift-tests" --cache-path "$PWD/build/swift-cache" --manifest-cache local
.venv-app/bin/python script/validate_app.py 'dist/K2 Updater.app'
```

`validate_app.py` 校验签名和所有 Mach-O 的双架构，复制应用到临时目录后，在清洁环境下验证两种架构的内置后台、HID 加载及完整模拟流程；不擦写 USB 设备。

内存模拟器和故障注入保留在开发验证中，不出现在正式窗口里。开发模拟数据保存在 `Offline Demo/`，备份清单标记 `simulation_only: true`。

## 验证范围

- 52 项 Python 回归、23 项 Swift 核心及编辑状态测试通过，包含文件往返、保留数据、图片方向／RGB565／BMP、备份落盘失败、双遍不一致、断连、错误 ACK、读回失败与恢复。
- 初版开发界面曾实际验证完整模拟升级、校验失败、备份 Finder 入口、升级中关闭/⌘Q 拦截和只读取消。0.2.1 已移除这些模拟入口，保留实际备份、升级及关闭保护。
- 0.3.0 正式窗口验证 `.pic` 导入导出逐字节一致、图片裁剪／缩放、坐标和撤销、工程保存／重开，以及无设备时写入禁用；不存在模拟 UI。两个架构的冻结后台均验证固件和三类资源的完整开发模拟读写／恢复流程。
- 原有 Python 核心曾在一台 K2 上完成 3.4 → 5.8 实机升级；0.3.0 开机图通过真实写入与完整扇区读回校验，用户确认重新上电正常显示。表盘背景和布局资源的实机效果、资源恢复刷写尚未验证。Intel 实机 USB 和 macOS 13 实机仍未验证，最低系统版本是构建目标。

0.4.0 的 E-Mark 文件模型、编辑草稿保留、无效输入保存阻止、连续输入撤销／重做通过自动检查。真实窗口已确认侧栏及页面打开、未连接设备时读写禁用；随后界面自动化连接中断，完整窗口编辑、文件对话框和关闭保护操作尚未完成复核。两个架构的冻结后台通过五类资源的完整模拟读写／恢复，全部 47 个 Mach-O 包含双架构，签名校验通过。E-Mark 真实设备读取与擦写尚未验证。

0.5.0 通过 68 项 Python、28 项 Swift 检查；百万样本规模验证、100 Hz 模拟采集 60 秒与完整落盘通过。全部 49 个 Mach-O 包含双架构；移动后的两个架构后台均通过 HID/SQLite 加载、曲线查询与三种文件交换，以及既有固件／资源模拟流程。真实窗口确认新版启动和曲线侧栏入口；随后自动化原生连接中断，页面操作与 PNG 实际渲染未完成验收。用户选择暂不连接设备，遥测实机验证及官方真实样本往返保留未验证状态。

0.5.1 接入普通模式 K2 5.8 实测：被动采集、暂停／继续、自动停止、三种格式交换通过；修正 100 样本每秒档的 USB 时间抖动采样漂移，并启用实机确认的遥测双校验。70 项 Python 检查通过；新版移动后台在 arm64／x86_64 下通过既有回归，49 个 Mach-O 双架构及本地签名通过。Swift 界面代码未修改。无负载和正常充电负载读数已对照；USB 电流符号保留。反向接线、长达一天采集、官方 Windows 文件往返及完整窗口操作仍未验收。详见[实机验证记录](k2-monitor-hardware-validation.md)。
