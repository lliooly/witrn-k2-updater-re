# 上位机性能优化记录

2026-10-10，本次优化针对实时采集时整页响应迟缓，以及历史曲线交互的重复计算。

## 修改

- 高频遥测独立为 `MonitorTelemetry`，只有读数、接收状态和样本计数订阅。录制、暂停、遥测过期及连接变化仍立即通知控制界面；没有节流或丢弃遥测更新。
- 命令栏和通道栏按可用宽度选择布局，替换反复测量候选布局的 `ViewThatFits`。窄窗口通过菜单保留全部通道。
- 游标读数和竖线独立订阅鼠标位置，避免每次移动都重新构建整组 `LineMark`；最近点查找改为二分，保留相同距离、重复时间点时的原有选择规则。
- 曲线查询结果的类型解码移到后台任务；保留查询代次、文件路径核验和待处理请求机制，防止过期结果覆盖当前记录。

采集频率、后台遥测读取、SQLite 落盘、图表点预算与极值保留、分段、统计和导出算法均未修改。曲线原有刷新周期也保持不变。

## 验证

- Swift 回归：40 项通过，包含连续 100 次遥测更新全部送达、没有触发整窗刷新，以及暂停/过期状态通知和游标查找等价性。
- Python 采集、记录、统计、遥测回归：18 项通过。
- 通用 Release 构建及应用签名校验通过，已更新 `dist/K2 Updater.app`。
- 真实 K2 设备预览和已有 SQLite 历史记录加载通过；负电流和断开后的曲线分段正常显示。
- 六张最终界面快照生成通过，检查了宽窄布局，窄窗口控件未溢出。

## 运行时证据与范围

`build/performance/before-live.sample.txt` 与 `after-live.sample.txt` 为优化前后主线程采样。SwiftUI `flushObservers` 更新链路占主线程采样的比例约从 69% 降至 17%；重复候选布局测量热点消失。该比例不是 CPU 使用率或帧率，采样也不能替代长时间录制和大型历史文件的压力测试。

后测采样发生在最终宽度监听修正之前；最终版本另经构建、回归及布局快照验证。原生界面自动化在最后的拖选验证期间连接中断，因此没有将拖选统计标记为完成手工验证。原有拖选坐标换算和统计请求流程保留，游标查询规则有自动回归覆盖。

## 第二轮：实时刷新仍有卡顿

同日继续优化曲线刷新：

- macOS 15 及以上采用系统 [LinePlot 批量绘线 API](https://developer.apple.com/documentation/Charts/LinePlot)，替换逐点 `ForEach` / `LineMark`。投影仅移除原实现同样忽略的缺失通道值，不减少点数。分段仍由原始 `segment` 标识，线性插值、坐标轴、游标和拖选接口保持原样；macOS 13/14 保留原绘制方式。
- 查询进行状态单独由小型进度指示器观察，避免每两秒的查询开始和结束让整窗重新计算；指示器预留尺寸，出现时不挤动控件。
- 自动曲线查询期间不再禁用缩放、通道和区间统计控件，新请求交给原有取消/待处理机制。设备断开且无记录时仍禁用这些控件。

本轮回归 42 项 Swift 测试通过（包括两个默认不输出快照的渲染用例）。新增 1200 点、7 通道投影检查，验证负电流尖峰、缺失温度和分段；另外实际生成并检查密集曲线快照，断点和尖峰均保留。

本轮实机预览采样 `second-before-live.sample.txt` 的主线程 SwiftUI `flushObservers` 为 844/3000，约 28%；批量绘线运行满一分钟窗口后的 `second-after-steady.sample.txt` 为 289/3473，约 8%。这些是短时调用栈采样比例，不是帧率或 CPU 使用率，且两次输入波形并非完全一致。上述后测包含批量绘线，未包含随后完成的查询状态隔离和控件禁用修正。

最终通用 Release 构建及签名校验通过，完整版本放置于 `dist/K2 Updater.app`。原生自动化的拖动调用导致工具连接中断，无法继续验证拖选或安全退出当前进程；没有强制终止设备预览。运行中的批量绘线版本保留在 `build/performance/running-vectorized-before-controls.app`，退出并重开主应用后启用最终控件修正。
