# K2 虚拟 E-Mark 配置管理设计

2026-10-08。用户已选择完整配置管理，整合进现有 SwiftUI Mac 工具。

## 功能与交互

侧栏新增“虚拟 E-Mark”。页面显示设备读取的配置、本地待写入配置和编辑器。

- 读取设备保存的虚拟 E-Mark 配置与复制数据。
- 管理最多 10 组配置：添加、复制、删除、排序及选择默认组。
- 编辑名称、PD 版本、VID/PID、认证标识、线材速度、电流、电压、连接类型、延迟、EPR 和软硬件版本。
- 提供原始 VDO 编辑与解析预览，修改已知字段时保留其他位及扩展数据。
- 兼容官方单条配置文件导入导出，并保存可重复打开的完整配置集合。
- 支持设备写入、完整扇区备份与恢复，显示写入结果和备份位置。

编辑不会立即改变设备。写入确认明确列出配置数量和默认组。设备上的虚拟 E-Mark 开关仍由 K2 菜单设置；本功能不宣称能远程切换运行模式或复制私有加密认证。

## 组件与数据流

- `K2Core`：独立配置记录、集合和文件编解码；统一位字段定义、长度、名称、计数和校验规则。
- SwiftUI 配置 Store：持有本地编辑状态、文件路径、选择和撤销记录，处理未保存修改。
- 配置页面：列表与参数编辑器，使用现有设备卡、操作进度和错误提示。
- Python：独立配置校验模块；通过已验证的 HID 帧和固定地址资源操作提供设备读取、写入及恢复。
- 后台请求继续绑定设备接口、序列号、信息摘要和确认时的文件摘要；共用单一忙碌状态，禁止同时进行固件或表盘操作。

写入前先完成格式校验和设备身份核验，再保存两遍一致的完整扇区备份。只更新明确选择的数据，保留扇区余量及复制区。擦写后逐字节读回，校验一致才完成会话；失败立即停止并报告阶段。

## 文件与兼容策略

官方单条格式保持原始字节兼容。未知位、扩展数据和未使用槽位在读取及编辑过程中保留，不通过重新生成默认值丢弃。完整集合另用带版本号的本地工程格式，保存原始记录及选中索引；个人配置、设备数据、官方样本和逆向中间产物不进入 Git。

无效或空白的设备数据仍能完整备份，并明确显示解析错误；禁止将未解析的数据自动修复后写回。名称输入采用可以确定往返的字节规则，拒绝会被静默截断或改变的字符。
