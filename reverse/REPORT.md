# WITRN UP V30 / K2 反向工程报告

本报告总结对 WITRN UP V30 Windows 主程序、其 HID 依赖和一份 K2 固件样本的静态分析。目标是记录可复核的协议证据并说明独立 Python 实现的边界；本仓库不分发被分析的厂商二进制、固件、反编译输出、IDA 数据库、设备备份或实机通信日志。

## 方法体与控制流

主程序集的大量方法在静态 IL 中呈短占位体，初始化逻辑会从嵌入资源恢复方法。对资源解码器进行 IL 静态解释后，恢复数据包括 292208 字节资源、650 处头部/元数据补丁及 1269 条方法体记录。记录与原程序集结构匹配，重定位 MethodDef RVA 后方法体均可解析。

进一步解析得到 574 组代理字段/方法 token。保护器 VM 资源含两个程序；RID 1768 的初始化逻辑可恢复 118 个混淆常量。结合代理映射和 VM 常量，重建的升级 worker 成功路径为：握手、读取设备信息和名称、擦除、写入、完整读回比较、写提交标记、发送命令 23 结束会话。

分析使用 IDA 定位程序集结构，使用 IL 静态解释和 ILSpy 处理托管代码。没有运行被分析的 Windows 升级程序，也没有尝试把 CLR IL 当作原生代码反编译。

## 固件容器与地址

5.8 样本显示 `.k2` 容器包含 48 字节头部和 716400 字节应用正文。256 项字节替换表用于整个容器解码；它与 Windows 程序自身资源的解码机制不同。头部字段、校验及 K2 GUID 见[协议说明](../docs/protocol.md)。

样本正文从 `0x08003800` 写入，解码后复位向量为 SP `0x20017D50`、Reset `0x08003B11`。样本容器长度会导致擦除 350 个 2 KiB 扇区。固件偏移 `0xC00` 是提交标记区域：全部应用字节读回一致后，升级器才将标记由 `FF FF FF FF` 写成 `FE FF FF FF`。

静态分析没有发现 XOR 和加法和构成数字签名或来源认证的证据。不要把格式校验当作可信来源证明。

## Python 实现与验证

`k2up/` 重建固件解析、HID 帧、同步命令、升级阶段、只读双遍备份和 CLI。`k2up/simulator.py` 是主机端流程模拟器，不是 Bootloader 仿真器。测试现在使用合成固件，不依赖厂商文件、个人设备数据或 USB 设备。

一次单台 K2 的 3.4 → 5.8 实机升级曾完成整份应用正文读回比较、提交标记核验和结束命令 ACK 检查。该单次结果不代表其他硬件或版本兼容；回刷恢复容器也没有实机验证。个人设备日志与备份不在仓库中。
