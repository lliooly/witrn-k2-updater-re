# K2 虚拟 E-Mark 静态分析

分析输入为本地 `WITRNUP.dll`，SHA-256：`315d274a3c8a1d546174b0f0566089377b278810a20a46bb817f14a75e4c0a37`。依据恢复程序集、IDA 托管代码列表、代理调用注释和官方简体中文资源，不执行 Windows 升级器。厂商文件、反编译输出和设备数据不随仓库发布。

## 单条官方文件

窗口的解密过滤器为 `wtemark|*.wtemark`。导出调用结构序列化写入流，导入检查末尾校验；文件是 66 字节紧凑结构，不是 JSON。

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 19 | 名称，最多 18 个字节字符加零结束符 |
| 19 | 1 | 附加字段（厂商打印为 bTBT），默认 0，保持原值 |
| 20 | 1 | PD revision：1 表示 PD 2.0，2 表示 PD 3.0/3.1 |
| 21 | 4 | Discover Identity 响应消息头 |
| 25 | 4 | ID Header VDO |
| 29 | 4 | Cert Stat / XID |
| 33 | 4 | Product VDO |
| 37 | 4 | Cable VDO |
| 41 | 4 | Identity 扩展 VDO |
| 45 | 4 | Discover SVIDs 响应消息头 |
| 49 | 4 | SVID VDO 1 |
| 53 | 4 | SVID VDO 2 |
| 57 | 4 | Discover Modes 响应消息头 |
| 61 | 4 | Modes VDO |
| 65 | 1 | `(sum(bytes[0:65]) + 0xA5) & 0xFF` |

32 位数均为小端。记录类型为 `\u009b\u009c.\u009b\u009b`，`StructLayout.Sequential, Pack=1`；嵌套结构长度分别为 24、12、8。

PD 编码通过编辑事件确认：窗口 PD 下拉框第 0 项赋值 1，其余赋值 2；打印代码显示 `pd_version + 1`。不能直接把界面版本数字 2／3 写入文件。SVID / Modes 分组通过重置方法确认：45 字节消息头设置命令 2，57 字节消息头设置命令 3。Identity、SVID 和 Modes 的重置消息头分别推导为 `FF00A041`、`FF00A042`、`8087A043`。

名称写入逐个将 .NET 字符转换为 byte，强制第 18 字节为零。本实现用可往返的 Latin-1 字符并拒绝中文、NUL 和超长输入，避免官方转换中的静默截断；读取时保留名称结束符后的原始字节，只有显式修改名称才重写名称区。

## 已识别位字段

字段来源为官方 getter/setter 的 start_bit / end_bit 参数。下拉框说明来自官方枚举字符串及 `zh-CN/WITRNUP.resources.dll`，保留项可以往返。标签描述的是厂商工具对该字段的解释，不保证任意 VDO 组合符合所有 PD 规范版本。

| VDO | 位 | 内容 |
| --- | --- | --- |
| ID Header | 0…15 | VID |
| ID Header | 21…22 | 连接类型 |
| ID Header | 26 | Modal operation |
| ID Header | 27…29 | UFP / 线材类型 |
| ID Header | 30 / 31 | 作为设备 / 主机 |
| Product | 0…15 / 16…31 | BCD device / PID |
| Cable | 0…2 | USB 速度 |
| Cable | 5…6 | 电流能力 |
| Cable | 9…10 | 最大电压 |
| Cable | 11…12 | 端口类型（官方 0：无源无 VCONN；1：有源有 VCONN） |
| Cable | 13…16 | 延迟 / 长度等级 |
| Cable | 17 | EPR |
| Cable | 18…19 | Type-C 插头类型（官方 2：公头；3：母座） |
| Cable | 21…23 | Cable VDO 版本 |
| Cable | 24…27 / 28…31 | 固件 / 硬件版本 |

编辑已知字段时仅更新对应掩码，保留所有未知位。原始编辑器支持上述 11 个 32 位字和附加字节，自动重算记录校验。新增配置是应用独立生成的可编辑模板，不是厂商预设或实际线材认证数据。

## 集合与地址

集合类型 `\u009c\u008d.\u009c\u008c` 同样采用 Pack=1：头字段 uint32、选中索引 byte、计数 byte、10 × 66 字节记录，总计 666 字节。头字段默认 `FFFFFFFF`，用途未确认，读取编辑时保留。有效计数为 0…10，默认索引需落在有效记录中；空集合索引为 0。仅校验有效记录，未使用槽位可以保留原始擦除值或旧数据。

K2 的 VID/PID 为 `0716:5060`，地址选择方法 `\u0094\u0089.\u0094\u008d` 的 K2 分支对应：

| 内容 | 起始地址 | 有效长度 | 擦除范围 |
| --- | --- | --- | --- |
| 复制数据 | `0x080E3000` | 66 | 2048 |
| 配置集合 | `0x080E3800` | 666 | 2048 |

两个扇区独立，背景区在复制区前结束，布局区从 `0x080E4000` 开始。页面写入配置集合不会擦除复制区或表盘。复制数据提供读取、导出和添加到集合；通过恢复入口可以恢复其完整备份扇区。

## 传输与主机保护

官方读取线程调用 RID 154 的内存读取封装（命令 11）；写入线程调用 RID 145 擦除封装及 RID 148 写入封装，底层分别使用命令 8、9，写入分包最多 40 字节，复用命令 4／5／22／23 的批次与结束机制。本项目复用已验证的 HID 帧编码和资源操作框架，不接受调用方提供任意地址。

写入前校验文件、摘要与设备身份，完整扇区双遍读取一致后持久化备份。写入合并原扇区中有效数据之外的字节，擦写后比较整个 2048 字节扇区。恢复核对备份清单摘要与设备身份，并先备份当前状态。错误立即停止；校验未通过不发送成功退出。

`.k2emark` 是本应用 schema 1 的 JSON 工程，type 为 `k2-emark-project`，bank 是完整 666 字节集合的 Base64。它与官方单条 `.wtemark` 不同。读取备份导出的 `.k2emarkbin` 是原始集合，不当作工程自动打开。

## 验证边界

合成记录验证字节布局、PD revision、校验、10 组容量、默认组、未知位与 inactive 槽位保留。模拟设备覆盖两遍备份不一致、落盘失败、错误批次、断连、读回失败及完整恢复。打包后的 arm64 / x86_64 后台均运行五类资源的模拟读写与恢复。

截至 0.4.0，E-Mark 真实设备读取和首次擦写尚未验证。此前固件和开机图的实机成功不能替代这一项。使用本工具编辑身份数据也不会改变实际线材能力；私有加密认证和设备运行时模式切换不在此次实现范围内。
